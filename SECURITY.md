# Security

Version 0.1.0 is under development and has not completed independent security review. See docs/PRIVACY.md and docs/IMPLEMENTATION.md for its guarantees, limits and unverified platforms.

Do not post real calendar data, OAuth client files/tokens, private subscription URLs, passphrases or vault files in public issues. Report a suspected issue using a minimal synthetic reproduction. For a sensitive vulnerability, contact the repository owner through an available private reporting channel before publishing exploit details.

No project-specific private reporting service or security-response timeline is promised. Normal logs should contain only safe categories and opaque local identifiers. Removing a log entry does not make an already-published secret safe; revoke affected credentials or shared links at the provider.
